localStorage: Halaman yang "Ingat" Datanya

Di materi Event, setiap kali halaman di-refresh semua perubahan langsung hilang. Sekarang halaman webmu bisa menyimpan data di browser — dari Dark Mode, nama pengguna, sampai daftar catatan.

Setelah ini kamu bisa:

  • Menyimpan, membaca, dan menghapus data dengan setItem, getItem, removeItem
  • Memahami bahwa localStorage hanya menyimpan string
  • Menyimpan array dan object memakai JSON.stringify dan JSON.parse
  • Memakai pola "baca saat halaman dibuka, simpan saat data berubah"
Mulai Belajar
Refresh tanpa lupa

1

PengenalanSetup & Apa Itu localStorage?

Kalian pasti pernah mengaktifkan Dark Mode di sebuah website, lalu menutup dan membukanya lagi — ternyata Dark Mode-nya masih aktif. Padahal di materi Event, setiap kali halaman di-refresh, semua perubahan langsung hilang dan kembali seperti semula. Bagaimana cara website mengingat pilihan kita? Jawabannya: localStorage.
DefinisilocalStorage adalah tempat penyimpanan kecil di dalam browser. Datanya berbentuk pasangan key: value (seperti object) dan tetap ada walaupun halaman di-refresh atau browser ditutup.
Aspek Variabel Biasa localStorage
Disimpan di Memori (sementara) Browser (tetap)
Saat halaman di-refresh ✗ Hilang ✓ Tetap ada
Saat browser ditutup ✗ Hilang ✓ Tetap ada
Dibaca perangkat lain ✗ Tidak bisa ✗ Hanya di browser & perangkat itu

4 Method yang Perlu Dikuasai
localStorage.setItem("nama", "Budi");        // SIMPAN (key, value)
const nama = localStorage.getItem("nama");   // BACA
console.log(nama);                           // "Budi"

localStorage.removeItem("nama");             // HAPUS satu data
console.log(localStorage.getItem("nama"));   // null (data tidak ada)

localStorage.clear();                        // HAPUS SEMUA data (hati-hati!)
Method Fungsi
setItem("key", value) Menyimpan data. Jika key sudah ada, nilainya ditimpa.
getItem("key") Membaca data. Hasilnya null jika key belum ada.
removeItem("key") Menghapus satu data berdasarkan key.
clear() Menghapus semua data milik situs ini.
Beri awalan unik pada nama key, misalnya rpl_nama, agar tidak bentrok dengan data proyek lain. Ingat juga bahwa key bersifat case-sensitive ("nama" ≠ "Nama").
2

Tipe DataSemua Nilai Berupa String

localStorage hanya bisa menyimpan string. Angka dan boolean yang kamu kirim akan otomatis diubah menjadi string saat disimpan.

Menangani data yang belum ada (null)
let skor = 0;                                       // nilai awal
const tersimpan = localStorage.getItem("rpl_skor");

if (tersimpan !== null) {                           // hanya jika ada data tersimpan
  skor = Number(tersimpan);                         // ubah ke angka
}
Data dari luar (form .value maupun localStorage) selalu string sehingga butuh Number() sebelum dihitung. Memeriksa tersimpan !== null secara eksplisit juga mencegah kesalahan karena Number(null) menghasilkan 0.
3

Struktur DataMenyimpan Array & Object (JSON)

Masalah saat menyimpan object langsung

Karena localStorage memaksa semua nilai menjadi string, menyimpan object secara langsung menghasilkan teks yang tidak berguna:

Solusi: JSON (stringify & parse)
JSONJSON (JavaScript Object Notation) adalah format teks untuk menyimpan array dan object:
• JSON.stringify(data) → mengubah array/object menjadi string (dipakai saat menyimpan).
• JSON.parse(teks) → mengubah string JSON kembali menjadi array/object (dipakai saat membaca).
Contoh dengan Array (wajib simpan lagi setelah diubah!)
Tujuan Kode
Simpan array / object localStorage.setItem("key", JSON.stringify(data))
Baca array / object JSON.parse(localStorage.getItem("key"))
1. Data diubah → harus disimpan lagi. localStorage tidak ikut berubah otomatis saat array/object di memori diubah.
2. Periksa null dulu sebelum memakai hasil getItem: jika key belum ada, JSON.parse(null) menghasilkan null yang bisa memicu error.
4

Pola IntiBaca Saat Dibuka, Simpan Saat Berubah

Pola Inti (Hafalkan!)

  1. SAAT HALAMAN DIBUKA → BACA dari localStorage (cek null), lalu tampilkan ke halaman.
  2. SAAT DATA BERUBAH (misal tombol diklik) → ubah tampilan, lalu SIMPAN ke localStorage.
Demo: Dark Mode yang Diingat

Klik tombol 🌙 Mode Gelap di Preview, amati munculnya rpl_tema: "gelap" di panel Local Storage, lalu tekan tombol Refresh. Untuk menguji kondisi awal lagi, klik Hapus Storage.

PengayaansessionStorage, Daftar Key, try/catch & Keamanan

Tambahan
sessionStorage: ingat selama tab belum ditutup

Browser juga menyediakan sessionStorage dengan method yang persis sama (setItem, getItem, removeItem, clear), namun datanya otomatis hilang saat tab ditutup. Cocok untuk data sementara satu sesi (misal isi form langkah demi langkah).

Fitur localStorage sessionStorage
Bertahan saat refresh ✓ Ya ✓ Ya
Bertahan saat tab ditutup ✓ Ya ✗ Hilang
Dibagikan antar tab situs sama ✓ Ya ✗ Per tab saja
Melihat semua key yang tersimpan
Mengamankan JSON.parse & penyimpanan dengan try/catch

Di aplikasi nyata, data di localStorage bisa rusak (misal diubah manual di DevTools) atau penyimpanan penuh/diblokir (mode privat). Membungkus JSON.parse dan setItem dengan try ... catch mencegah seluruh halaman berhenti karena error.

Bila situs yang sama dibuka di dua tab sekaligus, perubahan localStorage di tab A memicu event "storage" pada window di tab B — sehingga tema atau data bisa ikut tersinkron otomatis.
Catatan keamanan: innerHTML vs createElement
Pada Latihan B4 di slide, daftar catatan ditampilkan memakai innerHTML dan join agar ringkas. Di aplikasi sungguhan, memasukkan teks ketikan pengguna langsung ke innerHTML berbahaya (risiko Cross-Site Scripting / XSS jika pengguna mengetik tag <img onerror=...>). Biasakan memakai document.createElement("li") + li.textContent = teks seperti di Studi Kasus nanti.
6

DebuggingPeringatan, Kesalahan Umum & Latihan C

Peringatan Penting
  • Jangan simpan data rahasia (password, token login, nomor kartu). Siapa pun yang membuka DevTools bisa melihat dan mengubah seluruh isi localStorage.
  • Data hanya tersimpan di browser dan perangkat itu, tidak otomatis ikut ke perangkat lain.
  • Kapasitas terbatas (± 5 MB per situs) — simpan teks/JSON seperlunya saja.
  • sessionStorage memakai method yang sama persis, namun hilang ketika tab ditutup.
No Kesalahan Akibat Perbaikan
1 Menyimpan array/object tanpa JSON.stringify Tersimpan "[object Object]" JSON.stringify(data)
2 Menghitung langsung hasil getItem "5" + 1 menjadi "51" Number(getItem(...))
3 Tidak memeriksa null pada data yang belum ada Tampil Halo, null! atau error if (tersimpan !== null)
4 Key beda huruf besar-kecil: "Nama" vs "nama" Hasil null Samakan penulisan key persis
5 Mengubah array di memori tapi lupa menyimpan lagi Data kembali lama setelah refresh Panggil setItem lagi setelah diubah
Latihan C — Cari & Perbaiki Kesalahan

Jalankan tiap kode, tulis di komentar apa kesalahannya, lalu perbaiki hingga semua pemeriksaan lulus.

RingkasRangkuman (Contekan)

Dasar & Konversi
// SIMPAN, BACA, HAPUS
localStorage.setItem("rpl_key", "nilai");
localStorage.getItem("rpl_key");        // "nilai" atau null
localStorage.removeItem("rpl_key");
localStorage.clear();

// ANGKA (semuanya string!)
const teks = localStorage.getItem("rpl_skor");
let skor = teks !== null ? Number(teks) : 0;
JSON & Pola Inti
// ARRAY / OBJECT
localStorage.setItem("rpl_data", JSON.stringify(data));
const baca = localStorage.getItem("rpl_data");
const data = baca !== null ? JSON.parse(baca) : [];

// POLA UTAMA
// 1. Halaman dibuka → baca & tampilkan (cek null!)
// 2. Data berubah   → tampilkan & simpan lagi
