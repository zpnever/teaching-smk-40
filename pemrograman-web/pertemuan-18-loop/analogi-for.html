Memahami Perulangan for Langkah demi Langkah

Lihat bagaimana JavaScript menjalankan setiap bagian loop for — mulai dari inisialisasi hingga keluar dari loop — lewat analogi, animasi, dan simulator interaktif.

Buka Simulator → Lihat Analogi
Anatomi loop for Arahkan kursor / tab ke setiap bagian
for (let i = 1; i <= 5; i++) { console.log(i); }
1Inisialisasi

Membuat variabel penghitung. Dijalankan sekali di awal.

2Kondisi

Diperiksa sebelum setiap iterasi. Jika false, loop berhenti.

3Blok Kode

Perintah di dalam { } yang diulang setiap iterasi.

4Update

Mengubah penghitung setelah blok kode selesai dijalankan.

💡Perhatikan: bagian update (i++) ditulis sebelum blok kode, tetapi dijalankan setelah blok kode selesai.
01 · Analogi

Lari Keliling Lapangan 🏃

Bayangkan seorang pelari yang disuruh pelatih berlari beberapa putaran. Setiap kali melewati gerbang, petugas mengecek: "sudah cukup belum?" Itulah cara kerja loop for.

for (let putaran = 1; putaran <= 3; putaran++) {
    lariSatuPutaran();
}
🏃

📣

Inisialisasi let putaran = 1

Pelatih memberi aba-aba "Mulai dari putaran ke-1!" — hanya sekali di awal.

🚦

Kondisi putaran <= 3

Petugas gerbang mengecek setiap kali pelari lewat: masih boleh lari atau berhenti?

🏃

Blok kode lariSatuPutaran()

Tugas yang diulang-ulang: berlari satu putaran penuh (satu iterasi).

📋

Update putaran++

Papan skor ditambah 1 setelah satu putaran selesai, lalu kembali ke gerbang.

03 · Scope

Di Mana Variabel i Hidup?

Kurung kurawal loop seperti sebuah "ruangan". Variabel yang lahir di dalam ruangan itu tidak bisa dilihat dari luar.

🔒

Variabel i yang dibuat dengan let di dalam kurung for hanya dikenal di dalam loop. Setelah loop selesai, i dihapus dari memori.

let

Block scope ✅

for (let i = 1; i <= 3; i++) {
    // i hanya hidup di sini
}
console.log(i);
{ di dalam loop }
belum dijalankan
di luar loop
console.log(i) → ?
// output muncul di sini

Di luar loop, i sudah tidak ada sehingga muncul ReferenceError.

var

Bocor keluar ⚠️

for (var i = 1; i <= 3; i++) {
    // var tidak kenal block scope
}
console.log(i);
{ di dalam loop }
belum dijalankan
di luar loop
console.log(i) → ?
// output muncul di sini

Dengan var, i "bocor" ke luar loop dan bernilai 4. Ini sering memicu bug — karena itu gunakan let.
